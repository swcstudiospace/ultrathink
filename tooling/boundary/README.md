The core boundary rule keeps the host-agnostic code under `core/` free of host coupling: no module in `core/` may import a host SDK (`@oh-my-pi`, `@anthropic`, `hermes`, `prime-agent` packages), reference a host module by bare name, or use a relative path that resolves into `src/host/`, `src/claude/`, `src/grok/`, `src/muse/`, `src/cursor/`, or anywhere else outside `core/`. `check-core-boundary.ts` enforces it by walking every `.ts` file under `core/` and checking each static `import`/`export ... from`, side-effect import, dynamic `import()`, and `require()` specifier, printing each violation as `file:line` with the offending specifier. Run it from the repository root with `bun tooling/boundary/check-core-boundary.ts`; it exits 0 when clean and 1 on any violation or unreadable file.
