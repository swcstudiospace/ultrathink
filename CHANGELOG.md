## [Unreleased]

### Added

- GSD slash commands are planned. A prompt that is `/gsd-*` or `/skill:gsd-*` (also a plugin-qualified `…:gsd-*`) is planning input even when no skill file is installed: ultrathink plans the text after the command, or the command's objective when you typed nothing. `/ultrathink-quick` and the other `/ultrathink-*` commands still skip planning, and so do unknown commands such as `/model`. `bun scripts/cursor-plugin.ts install` copies the GSD command names the pstack stage table already knows into `~/.cursor/commands/<name>.md`, marked `ultrathink-cursor-gsd`. A file without that marker is left alone, and `remove` deletes only marked copies. The same files ship at `hosts/cursor/gsd-commands/`, and `.cursor-plugin/plugin.json` lists that directory beside `./hosts/cursor/commands`, which holds the Cursor control commands (`/ultrathink-on`, `-off`, `-skip`, `-track`, `-status`). The hook answers those controls itself through `bin/ultrathink` with host `cursor`. The pstack bridge (`ultrathink-managed`) is unchanged.
- Cursor host. `cursor` is a HostId with state under `~/.cursor/ultrathink` and the Claude CLI as its default planning engine. `bun scripts/cursor-plugin.ts install` registers a `beforeSubmitPrompt` hook (`ultrathink-cursor-managed`) that runs `hooks/engine.ts` and injects the plan as `additional_context`. The hook fails open: a missing Bun, a planner error, a child session, or the budget (`ULTRATHINK_CURSOR_BUDGET_MS`, default 180s) leaves the prompt unchanged. It does not replace the pstack bridge (`ultrathink-managed`) or substrate-managed hooks. `.cursor-plugin/plugin.json` loads the skills, including `ultrathink-cursor`, which hands new implementation work to the `a01-orchestrator` subagent once, with the Graph ID. `SUBSTRATE_ROOT` and `SWARM_ROOT` plus `--target` optionally run the substrate Cursor projector and `scripts/_install_cursor.py`; a missing checkout is skipped, and the installer never starts `swarm_run.py`. Substrate brief and plan events from this host use surface `cursor`. The plugin skill has a Grok Bot counterpart, `hosts/grok-bot/skills/ultrathink-cursor`, which tells that host not to spawn Agent Swarm. See [Install](docs/install.md#cursor).
- Omp shows a display-only card when planning recalls a lesson or skill, reads a substrate brief, RAGFlow, or knowledge, and when observe captures a teachable moment. Names and retain state only; no lesson or skill bodies.
- Policy as code (phase 75). Policy is Rego under `policy/`, tested with `opa test` and `opa check --strict`, and evaluated by a pinned OPA CLI (`policy/opa-pin.json`, verified by sha256 before it runs; pinned to OPA v1.21.3, checked against the release's published checksum). `policy/collect.ts` builds the input from the CI workflows, the systemd units and the `SECURITY_HEADERS` export, and `policy/check.sh` evaluates it, failing closed when the pin is missing or mismatched. `bun run policy:check`, `policy:collect` and `compliance` run them. The compliance report (`policy/compliance-report.ts`, `policy/controls.json`) maps each control to its evidence files with sha256 digests and reports PASS, PENDING or FAIL. Drift detection (`deploy/drift-check.sh`) is report only; its units are installed by hand and not enabled. Rego runs with the pinned binary on the machine that wrote it and passes; the `policy.yml` CI job has not run yet. This is an engineering mapping, not an audit attestation. The runbook section "Policy as code" lists the open items, including the retention gap (RET-D7) and the pending backup key custody (CRYPTO-BACKUP).
- Internal TLS and identity for the one internal hop (phase 69). With `ULTRATHINK_TLS_CERT`, `ULTRATHINK_TLS_KEY` and `ULTRATHINK_TLS_CLIENT_CA` set, the app listens on `127.0.0.1:8795` with TLS only and accepts only a client certificate that chains to the internal CA. The SPIFFE ID in that certificate, not a header, selects the route group: `edge/nginx` may proxy, and `ops/probe` may read `/healthz`, `/readyz` and `/metrics`. New settings: `ULTRATHINK_SPIFFE_TRUST_DOMAIN` and `ULTRATHINK_PLAINTEXT_LOOPBACK` (dev and local smoke only). The renewal units `ultrathink-cert-renew.service` and `.timer` renew the 24 hour leaves hourly. The issuing script `deploy/ultrathink-pki.sh` is in the repository. The TLS-only listener needs the certificate files it issues before it can start. The TLS-only listener needs Bun 1.4.0 or newer and refuses to start on an older runtime.
- Advanced audit logging (`services/ultrathink/obs/`): the hash chain gains Merkle anchors (an `audit_anchor` record every `ULTRATHINK_AUDIT_ANCHOR_EVERY` records) and `audit-cli verify --expect <seq>:<hash>` for copies kept off the host. Records stream to optional HTTP, Kafka REST Proxy v2 and syslog sinks (`ULTRATHINK_AUDIT_HTTP_URL`, `ULTRATHINK_AUDIT_KAFKA_REST_URL` with `ULTRATHINK_AUDIT_KAFKA_TOPIC`, `ULTRATHINK_AUDIT_SYSLOG`) through bounded drop-oldest queues, and security events stream without details or user agents. Declarative anomaly rules (`ULTRATHINK_AUDIT_RULES`) append `anomaly_detected` records. A tamper watch (`ULTRATHINK_AUDIT_WATCH_MS`, 100 to 1000 ms) raises `audit_tamper_detected`. The log seals files into read-only segments (`ULTRATHINK_AUDIT_SEGMENT_BYTES`) and prunes them after `ULTRATHINK_AUDIT_RETENTION_DAYS`, leaving an `audit_retention_pruned` boundary record. No SIEM endpoint or Kafka cluster is connected yet, and off-host anchor storage and pager delivery are open; runbook section 14 lists the steps.
- Intelligent rate limiting (Phase 70; `services/ultrathink/obs/fair-share.ts`, `obs/quota.ts`, `obs/forecast.ts`, `auth/penalty.ts`). The IP, principal and owner request windows follow an adaptive factor (`ULTRATHINK_ADAPTIVE_QUOTA_MIN_PCT`, `ULTRATHINK_LAG_TARGET_MS`). The HTTP pool and the plan slots are shared by priority class (owner, then connector, then bearer; `ULTRATHINK_PRIORITY_RESERVE_PCT`) and refuse at once, with 429 or `busy`. Repeated failures from one IP escalate a block (`ULTRATHINK_ABUSE_FAILURES_PER_MINUTE`, `ULTRATHINK_PENALTY_BASE_SEC`, `ULTRATHINK_PENALTY_MAX_SEC`). A per-minute load history gives a 15-minute forecast and a replica recommendation, persisted to `load-history.json` in the state directory; `ULTRATHINK_REPLICA_CAPACITY_RPS` is an uncalibrated placeholder. New series: the gauges `ultrathink_adaptive_quota_factor`, `ultrathink_load_forecast_rps` and `ultrathink_recommended_replicas`, and the counters `ultrathink_fair_share_refused_total`, `ultrathink_abuse_penalty_total` and `ultrathink_abuse_untracked_total`. Automatic scale-out, shared Redis Cluster state and SIEM delivery of abuse events are not built; runbook section 15 lists their prerequisites.
- Observability stack (Phase 71; `services/ultrathink/obs/`, `deploy/observability/`, runbook section 16). Spans for sampled requests and OpenRouter attempts are exported as OTLP/JSON when `ULTRATHINK_OTLP_ENDPOINT` is set, with no SDK and no new dependency; dropped spans and failed batches are counted. Log lines carry `spanId` beside `reqId` and `traceId`. The Prometheus family set is closed (`obs/metric-families.ts`) and gains breaker transitions, audit-chain notices, retention sweep duration and errors, export counters, anomaly gauges and SLO gauges. An EWMA detector watches event-loop lag, RSS and heap used. The `http_availability` SLO (objective 0.99) has an in-process 6 h error budget. `deploy/observability/` holds the Prometheus scrape and rules files (the runbook section 8 alerts, breaker-open and anomaly alerts, and multi-window burn-rate alerts) and a Grafana dashboard. `tracestate` stays dropped (D3). The collector, Prometheus host, alert routing and Grafana are not provided by this repo.
- Chaos experiments (Phase 73; `services/ultrathink/chaos/`, runbook section 18). Fault injection at the OpenRouter seam (status, reset, blackhole, latency) is armed only with `ULTRATHINK_CHAOS=1`, `ULTRATHINK_CHAOS_ENV=staging` and an absolute `ULTRATHINK_CHAOS_PLAN`; the service refuses to start otherwise, and the flag is off by default. Seven experiment templates, one per failure mode: three run in process (`upstream-5xx-breaker`, `upstream-latency-timeout`, `inflight-saturation`) and four are operator steps for a staging host. `bun run chaos` runs them, gates the rollback hook behind staging and prints a resilience score and trend from an append-only history. Scheduled runs are not shipped.
- Security scanning pipeline (Phase 72; `scripts/security-gate.ts`, `.github/security-policy.json`, `.github/workflows/security-scan.yml`): pull requests and `main` run a dependency audit, a license policy over both lockfile roots and Semgrep (`.semgrep/rules`); tag releases gate on the required check runs and attach the evidence to the GitHub release; the VPS release script runs the dependency audit before it switches releases; Dependabot covers `plugins/omp-token-opt`. Runbook section 19 lists what is still blocked.
- Point-in-time backup of the state directory (Phase 74; `deploy/ultrathink-snapshot.sh`, `services/ultrathink/store/snapshots.ts`, runbook section 5). Every 30 seconds `ultrathink-snapshot.timer` takes a `VACUUM INTO` copy of `ultrathink.sqlite` into `/var/backups/ultrathink/ring`, checks it, and copies `jobs/`, `sessions/`, `journal/`, `oauth.json` and `audit.jsonl` alongside it. The ring keeps every snapshot for one hour and the newest per five minutes up to 24 hours. The timer ships disabled until the staging measurement is recorded in the runbook.
- Restore, promote and monthly drill (Phase 74; `deploy/ultrathink-restore.sh`, `ultrathink-drill.timer`). `restore` picks the newest snapshot at or before `--at`, a named snapshot or an archive; it refuses while `ultrathink-web` is active, proves schema compatibility on a scratch copy before it places any file, keeps the replaced state in `.pre-restore-<stamp>/` and prints per-step timings. `promote --origin-fenced` is the manual off-host promotion. `drill` restores the newest snapshot into scratch every month; its off-host leg runs only when `ULTRATHINK_AGE_IDENTITY` is supplied and otherwise reports `SKIPPED`.
- Encrypted backups (Phase 74): with `ULTRATHINK_BACKUP_RECIPIENT` set, daily archives are written as `.tar.gz.age` to customer-held age recipients, verified in plaintext before encryption. Archives now include `audit.jsonl`, and a restore refuses a broken audit chain.
- `auth set-key openrouter` checks the key before storing it: the format must be `sk-or-…`, and one non-destructive request to OpenRouter's key endpoint must accept it. A rejected key is never stored, and a transient failure is retried three times. `--no-verify` stores the key after the format check only.
- Graph x Chain views for the hosted connector (`services/ultrathink/engine/graph-view.ts`): a structured graph view, a plain-text wave tree and a Mermaid flowchart, all derived from the finished session's graph (no second reasoning model). The plan text from `ultrathink_result` now leads with the wave tree in a code block, then the diagram, and tells the chat model to show the tree first. Mermaid 11 parsed and rendered twelve graphs in strict mode, including hostile titles. Whether Claude chat or Grok Chat renders a fenced Mermaid block is not verified, which is why the tree comes first.

It loads nothing external. It ran in a headless Chrome host harness, never inside Claude, and custom connectors are reported to render MCP Apps inconsistently, so the text result stays complete without it.

- A command catalog and six MCP prompts (`ultrathink`, `ultrathink-plan`, `ultrathink-think`, `ultrathink-last`, `ultrathink-status`, `ultrathink-quick`). The catalog is read from the plugin's command and skill files and decided per command in `COMMAND_OVERLAY`: 22 commands, of which 4 are native, 1 an alias, 1 a passthrough and 16 unsupported on the connector with a reason and an alternative. `docs/commands.md` has the table.
- Three connector tools, always listed: `ultrathink_graph` (`/ultrathink-think`), `ultrathink_sessions` (`/ultrathink-status` and the first step of `/ultrathink-last`) and `ultrathink_command` (every other `/ultrathink-<name>`). The hosted server now offers 10 tools, 9 without server planning.

- A local stdio server, `bin/ultrathink-connector` (`services/ultrathink/stdio/`; on Windows `bun <path>\services\ultrathink\stdio\main.ts`): newline-delimited JSON-RPC through the same protocol core as HTTP, with no planner, no OAuth and no network access. State goes to `ULTRATHINK_STATE_DIR` or the `connector` directory under the host state directory, logs to stderr at `ULTRATHINK_LOG_LEVEL`. One conformance suite runs against the tool host, the HTTP app and a spawned stdio process.

- Connector diagnostics: `/mcp` request log lines carry `mcpVersion` (the `MCP-Protocol-Version` header as sent) and `rpcMethod`, also for a request refused for an unknown version, so a hosted client's first connection can be read from the log. Runbook section 13 has the inventory, how to read that connection, a curl and stdio smoke checklist and the rate limits.
- Documentation for every client in `docs/how-to/use-ultrathink-in-chat.md`: Claude Desktop and claude.ai (plugin bundle and custom connector), Claude Code, Grok Chat and local stdio. It states that Claude chat and Grok Chat authenticate by OAuth only, that Grok never refreshes its tool list, that hosted Claude does not deliver server instructions, that the registration limit is 10 per hour per address, and that the connector has not been connected to either client yet.
- Planner telemetry and timing: each model call logs a `planner_call` event and feeds `ultrathink_planner_calls_total` and `ultrathink_planner_call_duration_seconds`; `ULTRATHINK_MODEL_TIMEOUT_MS` defaults to 0 (off), and a positive value sets a per-call limit, because `x-ai/grok-4.7` writes about 45 tokens per second and its large specification call takes 110 to 120 seconds; `ultrathink_result` waits up to 40 seconds per call.
- `ULTRATHINK_MODEL_REASONING_EFFORT` (minimal, low, medium or high; unset, `auto` and `default` all omit the parameter) is sent to OpenRouter as `reasoning.effort`. At the provider's default reasoning, `x-ai/grok-4.7` did not finish a plan in 6 minutes; at low it takes about 2 minutes. Measured on one prompt: gemini-3.6-flash 44 s, grok-4.3 62 s, gpt-5.6-luna 65 s, claude-haiku-4.5 111 s, grok-4.7 138 s (`docs/how-to/use-ultrathink-in-chat.md`).
- `ultrathink_uplift` and `ultrathink_result`: `/ultrathink <request>` now plans on the server in one call. The server runs the plugin's own pipeline (uplift, Graph of Thought, Chain of Thought, clarifying questions) with an OpenRouter model (`OPENROUTER_API_KEY` and `ULTRATHINK_PLANNING_MODEL`, for example `x-ai/grok-4.7`), bounded by per-run and daily token ceilings, with no tracking and no Notion or Linear. `ultrathink_result` returns the plan as text for server sessions and for finished client-driven sessions. Without a key the five client-driven tools work as before.
- MCP service: `POST /oauth/revoke` (RFC 7009), the `iss` parameter on authorization responses, an OAuth redirect allow list (`ULTRATHINK_OAUTH_REDIRECT_ORIGINS` extends it), Origin validation and `MCP-Protocol-Version` checks on `/mcp` (`ULTRATHINK_ALLOWED_ORIGINS` extends the allowed origins), protocol version 2025-11-25, request ids, one JSON access log line per request, `/readyz`, and a loopback-only `/metrics`.
- Deploy files for the service: a hardened systemd unit for a dedicated user, a release and rollback script, a daily SQLite backup with retention pruning, a Cloudflare-only nginx vhost with real client addresses and per-route rate limits, `docs/ops/runbook-ultrathink.md`, and a type check of `services/` in CI (`bun run check:services`).
- Database retention for the service: the daily maintenance job deletes runs not updated within `ULTRATHINK_RETENTION_DAYS` (default 30, any status) together with every row that references them, in one transaction. Child tables are found through their foreign keys, and a run with token spend dated today is kept so the daily ceiling never loses today's usage.
- Token-opt plugin (`plugins/omp-token-opt`) adds the v1.10 to v1.13 savings work: session token budget tiers, bounded dedupe, graph pointers and keyed cache, a remote savings sink, and a shared cache. The eight `TOKEN_OPT_FF_*` feature flags are all off by default, so default behaviour does not change.
- Measured token-opt plugin lives at `plugins/omp-token-opt`. It records tool-result savings, provider bill totals, and a bounded skim archive. Provider cache reads are not added into `saved`. `read_span` returns archived lines only and does not read the filesystem.
- Omp status bar shows provider bill totals (`bill N`, `out N`) and cache-stability flags (`prefix moved`, `tools moved`, `graph ready`) when `token-opt:savings` includes them. Those figures are not added into `saved`. A present flag other than 0 or 1 rejects the snapshot. A narrow planning line still keeps the current stage and `saved` when the session matches.
- Omp status bar hides `saved` and `before`/`now` when the live session id differs from the `token-opt:savings` session, so another session's `live.json` cannot paint this bar. A wide line may also show last-idle time (`idle Nms`) and cost (`cost Nc`) when the snapshot includes them. Those counts are not added into `saved`. A present optional field that is not a safe integer in range rejects the snapshot; absent fields stay omitted. A narrow planning line still keeps the current stage and `saved` when the session matches.
- Omp status bar shows an RTK session delta (`rtk +N`) and last payload size (`payload Nc`) beside `before`/`now`, and time-to-first-token (`ttft Nms`) in the `saved` chip, when `token-opt:savings` includes them. Those chips stay off the name when they would push a narrow planning line past the current stage. A present optional field that is not a safe integer in range rejects the snapshot; absent fields stay omitted. The new counts are not added into `saved`.
- Omp status bar shows measured token savings from `token-opt:savings` (`saved`, plus `before`/`now` when the line is wide) and restores the last snapshot from `~/.omp/agent/token-opt/live.json` on mount. A payload that fails the v1 checks is ignored.
- Omp status bar shows last-turn milliseconds in the `saved` chip and cache-hit percent beside `before`/`now` when `token-opt:savings` includes them; a wide line may also show graphify query latency. Milliseconds drop when they would push a narrow planning line past the current stage. A present optional field that is not a safe integer in range rejects the snapshot; absent fields stay omitted.
- Omp swarm teams. `/ultrathink-swarm <brief>|<brief>|…` fans out one detached AgentSwarm orchestrator lane per brief (`hooks/autonomous_run.py --runtime omp`), each lane isolated by its own `SWARM_DIR` state directory (Task Store, `kickoffs/` locks and an appended `run.log`), with `/ultrathink-swarm status` probing every lane's Task Store through `orch_status.py` and reporting per-lane task counts on one line. Env-only configuration: `ULTRATHINK_SWARM_ROOT` (absolute agent-swarm checkout; without it the command refuses with the reason) and `ULTRATHINK_SWARM_MAX_LANES` (default 3, cap 6). A resolved pstack cache appends the mapped `orchestrate` skills block to each lane's brief; an unresolved one drops the block silently. Replies are display-only Omp native cards in the TUI (counts-led lane cards with a safe malformed-data fallback; plain-text replies on hosts without a card surface), never a model turn, and the command works in child sessions With `swarm.autoRun: true` in the user config, a submitted prompt starting with an SDLC verb auto-spawns one AgentSwarm lane for itself (never a `/command` or a child session)..
- Native Omp dashboard. `/ultrathink-ui [overview|jev|moments|skills|card]` opens a keyboard-driven native dashboard (Overview, Jev, Moments, Skills panels) over the current session's latest saved Jev decisions and the current project's lessons, with explicit candidate confirmation, deterministic draft preview and separately confirmed Omp install through the existing teaching commands and installer guards; `card` publishes a bounded captured summary card labeled `captured — not live`. Browsing/refresh/preview are passive and local; guarded actions need the Omp TUI and are refused in subagent sessions, with the UI disabled, or outside the TUI. Retain acknowledgments are version-bound so a mid-flight capture cannot be marked synced; Esc during a dispatched action reports honestly that it cannot be stopped; detail, preview and Overview content wraps and scrolls within the real viewport, Skills shares one scroll budget between its settings and lesson list, list navigation stays available on narrow terminals, and compact cards always lead with lesson lifecycle counts. No browser, React, runtime dependency, model/provider loop or teaching-policy change. See [Commands](docs/commands.md#omp).
- Native Omp insight readability and focus. Lesson/draft whitespace and full bounded provenance survive wrapping and scrolling; affected panels disclose partial reads, policy-off actions stay unavailable, and layout-only refusals clear after resize. Expanded captured cards reflow recorded decision metadata within a 24-row physical budget, preserve policy/read-limit space and disclose capture/detail omissions. Opening shows local loading feedback, and returning from preview or closing preserves selected details and the composer draft.
- Native Omp action receipts preserve the complete bounded destination and promotion time. Busy controls identify the pending operation rather than a false terminal-size failure, and populated Overview distinguishes the saved Jev threshold from current promotion policy and qualifies latest-plan scope.
- Native Omp headless summaries count only displayed lessons and disclose text-budget omissions. Stored timestamps use the shared sanitizer before projection, and a missing selected identity no longer silently substitutes another record.
- Cursor pstack bridge. A `beforeSubmitPrompt` hook detects a `/gsd-*` command at the start of a line — a quoted example (including one that spans lines), an inch mark such as `12"`, or a mention later in a sentence is not an invocation — and injects local instructions to read the mapped pstack skills (`how`, `architect`, `arena`, `tdd`, `interrogate`, `no-comments`) by absolute `SKILL.md` path. Off unless `pstack.enabled` is true in the user config the hook reads; a project file cannot enable it, and `ULTRATHINK_PSTACK=0` forces it off. `bun scripts/cursor-hooks.ts install` and `remove` own one `ultrathink-managed` entry and never touch `gsd-managed`, `substrate-managed` or other entries. The installer stores a shell-quoted command under an absolute Cursor directory, it will not replace `hooks.json` when that file changes while the write is in progress, and it will not stage the hook when `hooks.json` parses but has the wrong shape. `install` and `remove` hold one lock across the staged-file snapshot, the copy, registration and restore, so a failed install cannot roll back a hook another install already registered. A dead holder's lock is reclaimed; a fresh empty lock is left alone. `ultrathink doctor` reports the deciding file, the resolved plugin, each stage's skills and whether the hook is installed; it follows the same off switch and the same first-parsed-file rule as the hook, and a missing skill is a warning only while the bridge is enabled. See [Run pstack skills beside GSD in Cursor](docs/how-to/use-pstack-with-cursor.md).
- `ultrathink doctor` checks config files, credentials, the state directory and the runtime without a network call. Unknown keys get a suggestion, ignored or adjusted values are named with the effective value, and `--json` prints a stable report. Exit 1 only when an error finding exists. See [Diagnose with doctor](docs/how-to/diagnose-with-doctor.md).
- `ultrathink prune` removes session records older than a cutoff, with `--dry-run` and a refusal below one day. `state.retentionDays` (user config only, default 0) opts into the same prune at most once a day from the plan path. An active ship and the carrier session are never removed, and prompt text is never printed. See [Session retention](docs/configuration.md#state-session-retention).
- A tag `vX.Y.Z` runs `.github/workflows/release.yml`, which re-runs the gates, checks the tag against every manifest and `CHANGELOG.md`, and opens a GitHub release from that changelog section. It does not publish to a package registry. `bun scripts/release-check.ts` is what the test suite runs so a drifting version cannot merge.
- Opt-in desk gateway backend for Hindsight, RAGFlow and the substrate brief. `hindsight.backend`, `ragflow.backend` and `substrate.backend` stay `direct` unless set to `gateway`. A `gateway` section (`url`, `seat`, `timeoutMs`) plus `DESK_GATEWAY_TOKEN` or a stored `desk-gateway` credential calls `desk_memory_recall`, `desk_memory_retain`, `desk_docs_search`, `desk_brief` and `desk_event_emit` on `<url>/mcp/<seat>`. No Hindsight or RAGFlow key is read on that path. `ULTRATHINK_GATEWAY=0` forces the direct clients. Status lines report `gateway · ready` or `gateway · unready` with the reason.
- Grok Bot native host. `bin/ultrathink-grokbot` runs `planPrompt` with a journal completer: every completion the engine needs is written to `<stateDir>/journal/<session>/pending/`, the bot answers it by following the plugin's own system prompt, `answer` validates it the way the engine parses it, and the next `plan` replays it. Jev decisions are journalled for resumed runs. Shipping is forced off. `track payloads` / `track record` bridge `createTracking` to the bot's Linear and Notion connectors; `answers` folds chat replies into clarifications (the AskUserQuestion hook's job); `teach digest` builds a `TeachDigest` from the bot's turns for `teach observe` (the Stop hook's job); `prompts build` derives validated cloud-agent prompts per node; `review read` reads the Greptile score and threads; `skills status` reports drift between the 21 staged skills in `hosts/grok-bot/skills` and the installed copies. `ultrathink.discovery.json` lists `grok-bot` with status `native-adapter`, delivery `skill-protocol-cli`, `adapterPresent` true and `compatibilityVerified` false. See [Use with Grok Bot](docs/how-to/use-with-grok-bot.md).
- `ultrathink doctor` gains a `memory` section: outbox age (warning after 24 h), the last `teach observe` runs (error after three hard failures in a row, `distiller failed`, `lesson not saved`, `no engine` or `error`, showing the reason), never-processed observe digests in the inbox (warning after an hour) and the number of local lessons. `ULTRATHINK_TEACH=0` turns the section into one info line.
- Plan-first Claude authentication: `claude.auth` (user config only, `"plan"` or `"api-key"`, default `"plan"`) replaces `claude.fallbackToLogin`, which was added earlier in this unreleased list and never shipped; the key is removed and an old value is ignored. With `plan`, every `claude -p` child (the planner, the Teachable Moments distiller and the ship judge) runs without `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX` and `CLAUDE_CODE_USE_FOUNDRY`, so the Claude plan login (or `CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token`) authenticates and the calls draw from the plan's usage limits. `api-key` passes the environment through unchanged. A project file cannot set it. See [`claude`](docs/configuration.md#claude-the-claude-engine).
- `claude.fallbackToGrok` (user config only, default `false`): when on, a Claude call that fails with an authentication, billing, plan-limit, rate-limit, overload, model-unavailable, missing-CLI or network error is retried on the Grok route. It is opt-in because the prompt text then goes to xAI. A project file cannot set it.
- `grok.fallbackModels` (default `[]`; a project file may set it, like `grok.model`): the Grok route tries `grok.model` first, then these models in order, and skips a model the login cannot use (HTTP 429 with a limit of 0, HTTP 403 "requires a Grok subscription", or the CLI's "unknown model id"). Entries are trimmed and deduplicated, at most 8.
- A failover chain between the Claude and Grok routes. Within one chain, that is one planning run in one process, a failed candidate is skipped for a cooldown so the later stage calls of that run do not retry it: authentication 10 minutes, billing 60 minutes, plan limit 15 minutes, rate limit 60 seconds, overload 30 seconds, model unavailable 60 minutes, missing CLI 60 minutes, network error 30 seconds. The cooldown is not kept across prompts: each new hook process tries the configured model once, and a refused model costs one quick failed request before the fallback answers; the hosted service keeps its chain for the life of the process. Timeouts, aborts and other errors do not fail over. A successful failover is not an error: the summary gains a `Failover · claude:claude-haiku-5-5 → grok:grok-build-0.1 (plan-limit)` segment and the session record stores it as `engineFailover`, on the hosted service as well as locally; a total failure still reports `Engine error · ...`.

The digest now takes a user-attributed `skill-prompt` as the user turn: the submitted draft, else `/skill:<name> <args>`, never the skill body (`src/teach/digest.ts`). A run that resumes on an agent-side message alone (an async result, a ship nudge) still has no prompt of yours and is not captured. The host builds the digest in its own process, so restart it after updating the plugin.
- `ultrathink doctor` reported the age of the newest lesson from file modification times, which Hindsight confirmation and recall move, so a store that had captured nothing for a week read as one hour old. The `memory` section now reads each lesson's `lastSeenAt` and `createdAt`, and warns when the newest capture is over 3 days old, a session record was written in the last 24 hours and no `teach observe` run was recorded in the last 3 days (a run that found nothing teachable proves the hand-off works). It never warns in `explicit` capture mode.

### Security

- Model CLIs that ultrathink starts (`claude -p`, the Grok CLI, the Muse engine) run with `ULTRATHINK_OPENROUTER_KEY` and `OPENROUTER_API_KEY` removed from their environment in every auth mode, so the Jev key is never inherited by a child process.

The Vercel rail calls the fixed `https://ai-gateway.vercel.sh/v4/ai/evaluation-model` with the model in the `ai-model-id` header (`typesafe-ai/jev` for the default alias) and sends only the state and questions — no provider preferences, session id or trace. `bin/ultrathink status` and `decisions check` show the rail (`provider vercel|openrouter`) and the key source, never the key. Vercel serves Jev only: engine selection and the Graph of Thought never reference it (proven by tests).
- Omp and Hermes plan with the session's active model: under `think.engine: "auto"` on those hosts, the engine follows the model in use (Hermes forwards its hook payload's model; Omp reads its session file's last `model_change` entry) instead of always using Claude. Unknown families and unreadable sessions keep the Claude default; an explicit `think.engine` still wins; a detected Grok without a login fails over to Claude, never skips.

### Changed

- `think.engine` now defaults to `"auto"` (each host plans with its own engine) instead of `"claude"`, and accepts `"muse"`. The per-host override is now `bin/ultrathink grok engine auto|claude|grok|muse`. To keep the old behaviour, set `"think": { "engine": "claude" }`.
- Hermes: the plan reaches the model as a short handoff (spec path, state file, Graph ID and kickoff instruction) instead of the full specification, because Hermes replays hook context in every turn and spills pieces over 10,000 characters to a file.
- `ultrathink-kickoff` fails open when Notion or Linear is down, unreachable, rate-limited or unauthorised: it creates no rows by hand, says which tracker failed in one line, and continues. The manual MCP fallback is only for when `track complete` itself cannot run. On Hermes it asks blocking questions with one `clarify` call (at most 5 questions of up to 4 choices, default first) and uses the defaults when no user is available.
- `ultrathink-sync` finds rows by Graph ID only (the Notion Task by the session record's `tracking.notion.taskUrl` or its `Graph ID`, the Linear issues by the session's tracking refs or the `ultrathink graph <id>` footer), never by branch, PR title or repo. It never creates rows, never clears `PR URL` or `PR #` in a turn without a pull request, fails open when Notion or Linear is down, unreachable, rate-limited or unauthorised (one line naming the tracker, no retries, the turn continues), and ends with `ultrathink-mcp session mark --state <file> synced`, which stops the Hermes end-of-turn nudge.
- The Agent Substrate brief is opt-in. ultrathink no longer requests a brief from a built-in local address; it asks only when `substrate.url` or `SUBSTRATE_URL` is set. The kickoff skill treats registering the graph with Agent Substrate as optional. To keep the old behaviour, set `substrate.url` (or `SUBSTRATE_URL`) to your Agent Substrate server's URL.
- Ship is opt-in: `ship.enabled`, `ship.autoMerge` and `ship.deleteBranch` now default to `false`. With the defaults, no skill run pushes, opens a PR or merges, and the plan, the end-of-run nudge and the ship skill only promise a merge when `ship.autoMerge` is on. `bin/ultrathink-ship` still works when run by hand, but `merge` refuses unless `ship.autoMerge` is `true`. To keep the old behaviour, set `"ship": { "enabled": true, "autoMerge": true, "deleteBranch": true }`.
- Grok `shunt` transport: `grok.shuntBaseUrl` and `grok.shuntModel` now default to `""`, and there is no built-in gateway. With `transport: "shunt"` and no `grok.shuntBaseUrl`, each engine call fails with an error naming that key; the prompt gets the conservative fallback spec and no rows are created. Claude is not used instead (`grok.fallbackToClaude` only applies to a missing Grok login). An empty `grok.shuntModel` sends `grok.model`. To keep the old behaviour, set `grok.shuntBaseUrl` to your gateway's URL and `grok.shuntModel` to the model name your gateway expects.
- `ultrathink-mcp auth login` no longer runs `tailscale` on its own. Over SSH the default is the loopback callback, with port-forwarding and paste-back instructions; a line mentions the Tailscale option. To keep the old behaviour, pass `--tailscale` or set `ULTRATHINK_OAUTH_TAILSCALE=1`.
- `scripts/mcp-register.ts` keeps a same-named `notion`, `linear` or `greptile` MCP entry that is not ultrathink's (its command does not end in `/bin/ultrathink-mcp`) and reports it as `kept`. ultrathink entries from another clone are still replaced, and entries that already match are reported `unchanged`. To keep the old behaviour of overwriting every same-named entry, pass `--replace`.
- `bin/ultrathink`, `bin/ultrathink-mcp` and `bin/ultrathink-ship` exit 127 with `ultrathink: bun not found. Install Bun 1.2 or later (https://bun.sh) or set BUN=/path/to/bun` when Bun is missing, and keep Bun's exit status when it cannot start. They used to exit 0. The hooks still exit 0, so a missing Bun never blocks a prompt. Scripts that relied on exit 0 should install Bun or set `BUN`.
- Grok Build state lives in `$GROK_PLUGIN_DATA/ultrathink`, else `${GROK_HOME:-~/.grok}/plugin-data/ultrathink`: `GROK_HOME` is now honoured by the engine, the Grok rule, the `ultrathink-plan` skill and `mcp-register` (`scripts/setup.ts` already honoured it). If you set `GROK_HOME` and want to keep your Grok control state, move `~/.grok/plugin-data/ultrathink` to `$GROK_HOME/plugin-data/ultrathink`.
- Grok Build users must re-run `bun scripts/setup.ts apply` after updating, so `${GROK_HOME:-~/.grok}/hooks/ultrathink.json` gets the new PR-sync matcher and the Grok rule gets the new state paths. The Grok plugin itself still needs `grok plugin enable ultrathink` once.
- `scripts/setup.ts`: the `CLAUDE.md` block says the plugin *can* track and applies only when tracking is configured; the Notion and Linear MCP servers are detected by exact name; the printed Hermes steps use `$HERMES_HOME` and say that the hook cap is a global Hermes setting of at least 105 s (600 recommended). Run `bun scripts/setup.ts apply` again to update an existing block.
- Missing-credential messages for Linear and Greptile name both routes: `ultrathink-mcp auth login <provider>` (OAuth) or `ultrathink-mcp auth set-key <provider> --stdin` (API key). Notion stays OAuth-only.
- Shipped text, hook matchers and examples carry no project-specific names: the tracking instructions give `Refs ENG-12` as the example identifier, and the PR-sync hook matches any MCP server's `create_pull_request`, `pull_request_create` or `createPullRequest` tool.
- Ship: a failed or timed-out Greptile review is re-triggered on the next `review` call (up to `ship.reviewRetries` per head commit) instead of blocking the ship after two failures on one commit. `review` output gains `passed`. To keep the old behaviour, set `ship.reviewRetries` to `1`.
- Ship: `ship.maxRounds` now counts only completed reviews below 5/5 or with open threads; failed and timed-out reviews never count.
- Ship: once the head's review passed (5/5, no open threads), `merge` keeps retrying until the PR merges: within each call up to `ship.waitMs` it retries pending CI, mergeability not computed, unreadable PR state or threads and transient GitHub errors, returning `waiting: true` and `next: "run merge again: …"` when the call's time runs out. Past `ship.mergeTimeoutMs` on one head commit, or on a terminal GitHub refusal (missing permission, requested changes, a closed PR; a branch-protection hold such as a missing approval is retried until the bound instead), the ship blocks and the PR comment lists the attempt history. Conflicts, failing CI, a moved head or a review below 5/5 go back to the agent (`next`), never merge. `run` merges within its own `ship.waitMs` budget when the review passed. The merge gate is unchanged.
- Ship: a PR merged outside the flow without a passing Greptile review of its head is reported blocked (`PR was merged outside the ship flow before its review passed`), never recorded as a ship merge.
- Jev decisions are always on: `decisions.enabled` is ignored in every file, and every listed point is consulted as soon as a key exists for the resolved rail. `ULTRATHINK_DECISIONS=0` is the only off switch. To keep the old behaviour (no Jev requests), set `ULTRATHINK_DECISIONS=0` in the host's environment, or remove the stored keys and unset `AI_GATEWAY_API_KEY` and `OPENROUTER_API_KEY`. The `Decisions:` status line and the `decisions check` line gain a `provider vercel|openrouter` segment, and the no-key message names both key routes.

### Removed

- The built-in Agent Substrate address. Set `substrate.url` or `SUBSTRATE_URL` to use Agent Substrate.
- The built-in Grok `shunt` gateway URL and model. Set `grok.shuntBaseUrl` and `grok.shuntModel` to use the `shunt` transport.
- The automatic Tailscale probe and `tailscale serve` route in `ultrathink-mcp auth login`. Use `--tailscale` or `ULTRATHINK_OAUTH_TAILSCALE=1`.
- The PR-sync hook's matcher entry for one private MCP server name; the generic matcher above covers it.
- The in-memory Hindsight stand-in (`src/integrations/hindsight-client.ts`), its smoke script (`scripts/hindsight-smoke-test.ts`) and `docs/hindsight-client.md`. No code reads the old stand-in switch or the old endpoint variable.

### Fixed

- Notion rows are created with their properties again. The hosted Notion MCP now returns a data source's schema as JSON inside a text field, which the schema reader missed, so every Task, Issue and Sub-Issue row was created empty (no Item, Level or Graph ID) while tracking still reported complete, and lookups by Graph ID found nothing. The reader now parses the schema inside text payloads, and a schema read that misses the core names sends every property unfiltered, so a mismatch fails the create loudly instead of recording empty or partial rows.
- Hermes: plans are no longer dropped by Hermes' plugin hook cap. The planner reads the cap Hermes enforces and stops at `min(540, cap − 15)` seconds; below a 105 s cap (a deadline under 90 s) it doesn't start Bun and logs one warning naming `hermes config set plugins.hook_callback_timeout 600`. Nothing sets the cap for you: Hermes defaults to 30 s, so run that command yourself (at least 105 s, 600 recommended; it is a global Hermes setting that applies to every plugin). `scripts/setup.ts apply` prints the command but does not run it. On the deadline the plugin kills Bun's whole process group, so no engine call outlives the hook.
- Hermes: the prompt hook no longer creates Notion or Linear rows. `ultrathink-kickoff` creates them with `ultrathink-mcp track complete --state <file>`, so a plan that Hermes abandons can't leave orphan rows.
- A prompt that references an existing ultrathink graph (`graph ut-<id>-<8 hex>`, as dispatched workers and Linear issue footers do) is no longer planned again as a new graph on any host. Prefix it with `uplift:` to force a plan. On Hermes a bare skill preamble with no task is skipped too.
- Muse: the planning hook no longer recurses into itself. `muse exec` runs hooks with a sanitized environment, so the child marker never reached nested hooks and every nested plan re-planned; engine prompts now carry a sentinel that nested hooks recognise and skip.
- A dead engine is loud instead of silent. The session record keeps the first engine error (redacted, one line, at most 500 characters) and the stages that fell back to boilerplate, and the context warns up front — naming the engine, the error or the degraded stages, and the fix — instead of presenting generic text as a terse real plan with tracker rows to come. Without a track plan, the tracking section says no rows will exist rather than telling kickoff to finish missing ones, and kickoff resolves clarifications from the record instead.
- Hermes and Omp: stateless skips (`raw:`, commands, already uplifted XML, graph references, trivial acknowledgements) run before an engine is selected, and the Hermes plugin skips prompts that start with `/` and already uplifted XML before starting Bun.
- Hermes integration: the handoff's human-in-the-loop step asks blocking questions with one `clarify` call (at most 5 questions of up to 4 choices, recommended default first) instead of the nonexistent `AskUserQuestion`, and names Hermes' `todo` and `delegate_task` tools. With `/ultrathink-skip` armed, a trivial or bare-preamble prompt on Hermes and Omp now uses up the skip, as on the other hosts. The plugin strips a shared-session `[Name] ` sender tag that names the current sender before its skips and plans the untagged text (a `[label]` the user typed stays), and takes the planner's working directory from `TERMINAL_CWD` before its own. An armed skip is consumed before engine selection, so an unavailable engine cannot leave it armed. A PR a `delegate_task` subagent really opened (its own `gh pr create`, matched to the parent through `subagent_start`) nudges the parent; a delegate result that only cites a PR does not. Both sync nudges pass `graphId=`, and `ultrathink-sync` prefers it over a state file that a newer plan has since replaced. The ship skill loads `ultrathink:ultrathink-sync` by its Hermes name, and the plan skill falls back to `~/.hermes/ultrathink` when `HERMES_HOME` is unset.
- Notion rows whose create reply links to `https://app.notion.com/…` are counted as created.
- PR sync: tool names count as PR creation only when they end in the create verb, so `create_pull_request_review` and `create_pull_request_with_copilot` no longer link tracked rows to an unrelated pull request.
- `scripts/setup.ts` works from a clone whose path has spaces or non-ASCII characters, no longer counts lookalike MCP server names (such as `notion-foo`) as installed, removes its `ultrathink-setup-state.json` on `rollback`, and prints (without running) the Claude Code plugin uninstall commands.
- `scripts/mcp-register.ts` no longer rewrites Muse's entries on every run when only key order or a default `type: "stdio"` differs, verifies each removal, and backs up the `config.toml` under `GROK_HOME`.
- `scripts/mcp-register.ts` reads and backs up the `config.yaml` of the active Hermes profile (`<Hermes home>/profiles/<name>/config.yaml` when a profile other than `default` is active, or when `HERMES_HOME` points at a profile directory) instead of always the root `config.yaml`. When the active profile cannot be resolved, it backs up nothing and says so.
- `scripts/setup.ts apply` keeps the MCP servers recorded as added by earlier runs, so `rollback` still removes them after a re-run. `rollback` keeps its state file when a removal fails, prints the error and the manual `claude mcp remove` command, and retries on the next run.
- `scripts/setup.ts rollback` never removes a Notion or Linear MCP server you replaced after `apply` added it (for example with the gateway through `mcp-register --replace`): it removes a server only while `claude mcp get` still shows setup's user-scope HTTP entry with the hosted URL, reports a replaced one as left in place and a missing one as already removed.
- `scripts/mcp-register.ts` decides ownership from the user-scope entry only, the scope it adds to and removes from: a same-named project- or local-scope entry in Claude Code or Grok no longer blocks registration and is never touched.
- The `/ultrathink-off`, `-on`, `-skip`, `-status` and `-track` command files work when `CLAUDE_PLUGIN_ROOT` is not set: the model asks you for the ultrathink directory and runs `bin/ultrathink` from there, instead of failing.
- Ship: the done assessment is no longer blind after `gsd-autonomous` archives a milestone. When `.planning/phases` has no `*-VERIFICATION.md`, the latest `.planning/milestones/<version>-phases/*/*-VERIFICATION.md` statuses must all be `passed` (each other status is a gap; a phase without a readable verification counts as `missing`, and no verifications at all is a gap), and the milestone's audit status and scores go to the judge as evidence, instead of the judge seeing "0/0 phases, verification none".

### Security

- The Grok `cli` transport runs the `grok` process in a private per-process temporary directory (mode 0700) instead of a fixed, shared directory under the system temp directory.
- When `CLAUDE_PLUGIN_ROOT` is not set, the command files tell the model not to search for or run any other `bin/ultrathink`; it runs only the one in the directory you name.
- With no configuration, ultrathink no longer contacts an Agent Substrate server, runs `tailscale`, or pushes, opens pull requests or merges; each needs an explicit opt-in (see **Changed**).
- Jev decisions: `ULTRATHINK_DECISIONS_URL` is accepted only as an `https://openrouter.ai/…` URL or an `http://` or `https://` URL on `localhost`, `127.0.0.1` or `[::1]`, never with a user name or password in it. Any other value is ignored and the default endpoint is used; the `Decisions:` status line and `decisions check` then end with ` · ULTRATHINK_DECISIONS_URL ignored (must be https://openrouter.ai/… or a loopback URL)`. Only the URL's origin and path are used and printed. The Decisions client never follows a redirect, so the OpenRouter key cannot be forwarded to another host.
- Jev decisions: a project file (`<project>/.claude/ultrathink.json`) can only tighten consent: `decisions.zdr` only from `false` to `true`, and `decisions.points` is intersected with the list from the user files (`decisions.enabled` is ignored in every file). A repository sends nothing anywhere unless you stored or set a key, and it cannot turn zero data retention off. The two user files merge these keys as usual.
- Ship: in gate mode with `ship.autoMerge: true`, a Jev verdict never stands in for a missing or unusable LLM judge verdict: the result is `no judge available` or `assessment unavailable: …` exactly as without Jev, and the Jev decision is recorded with the action `none`. Jev can still veto a usable "done".
- `bin/run-bun` passes `--no-env-file` to Bun, so on Bun 1.3.3 and later the `.env*` files of the repository you work in are no longer loaded into ultrathink's hooks and CLIs, where they could set `OPENROUTER_API_KEY`, `ULTRATHINK_DECISIONS_URL` or any other variable ultrathink reads. Bun 1.2.x ignores the flag and still loads them.
- Lesson text is redacted (`src/teach/redact.ts`) before it is stored or leaves the machine. A project file (`<project>/.claude/ultrathink.json`) cannot opt you into Hindsight, RAGFlow or Teachable Moments: `hindsight.enabled`, `ragflow.enabled`, `ragflow.ground` and `teach.enabled` can only be turned off there (`teach.capture` can only be lowered). Jev decisions are always on but send nothing without your key, and there `decisions.points` can only drop points.

## [0.3.0] - 2026-09-25

First public release, licensed under AGPL-3.0-or-later.

### Added

- Ship flow: the `ultrathink-ship` skill, driven by `bin/ultrathink-ship`, checks that the task is really done, opens a pull request into the repository's default branch, runs Greptile reviews until the score is 5/5 with zero open comments, squash-merges only when that gate passes, and cleans up the branch.
- `/ultrathink-quick`, `/ultrathink-skip`, `/ultrathink-off`, `/ultrathink-on`, `/ultrathink-track` and `/ultrathink-status` slash commands on all five hosts: send one message without planning, skip planning for the next message, turn planning or Linear/Notion tracking off and on, and show the current state.
- `ultrathink-mcp notion init --parent <page>` creates the Agent Task Graph database in your Notion workspace; `--write-config` saves it to your config.
- Host-neutral config file `~/.config/ultrathink/config.json` (under `$XDG_CONFIG_HOME` when that is set). `~/.claude/ultrathink.json` and `<project>/.claude/ultrathink.json` still apply on top of it.
- Muse, Hermes Agent and Omp hosts, with one MCP gateway (`bin/ultrathink-mcp`) that serves Notion, Linear and Greptile to every host from a single credential store. Omp also gets a live status bar and plan cards.

### Changed

- Notion and Linear targets no longer default to the author's workspace. Set `notion.dataSourceUrl` and/or `linear.team` (or run `ultrathink-mcp notion init`); with neither set, tracking is off.
- The MCP gateway reports an upstream rate limit as a rate limit, with the retry delay when it is known, instead of as an authentication error.

### Fixed

- Ship: a passing review whose pull request is only waiting on CI, mergeability or conflicts is no longer counted as a failed round, so it cannot block the ship at `maxRounds`, and `review` now says what to wait for instead of "fix the listed findings".
- Ship: a transient Greptile tool or network error during a PR-mode review is reported as `pending` and retried on the next call, instead of being recorded as a failed round that counts toward `maxRounds`.

### Security

- Nothing notable in this release.
