# Agent matrix: CLI agents GSD-Core supports vs. Ultrathink adapters

Research date: 2026-11-16. Companion to `docs/gsd-core-findings.md`; short names (`UP:`, `LOCAL:`, `INSTALL.js`, `MATRIX`) are defined there.

## How to read the columns

- **Install method**: how GSD-Core itself reaches the agent today (`npx @opengsd/gsd-core@latest --<flag> --global`, or a native plugin path). Sources: UP:docs/how-to/install-on-your-runtime.md and UP:docs/ARCHITECTURE.md:1039-1062.
- **Gating** (workstream 1, CompletionGate): can a plugin hold or deny the user's prompt or turn until the uplifted XML prompt has finished generating? Values: `yes`, `partial`, `no`, each followed by `UNVERIFIED` unless proven by a test or a live run. Nothing below is proven: no Ultrathink test exercises a CompletionGate on any of these agents, and GSD's own hooks are advisory or per-tool guards, not a prompt gate (UP:docs/ARCHITECTURE.md:294-298). `partial` means the host documents a hook event that can block before the model acts (per MATRIX evidence quotes), but no one has shown it can wait on a slow external plan.
- **Model routing**: whether GSD-Core resolves a concrete tier-to-model map for the agent (LOCAL:bin/shared/model-catalog.json:9-99, `runtimeTierDefaults`), and whether the host lets a plugin choose a model (`modelMode`, MATRIX). "Cheapest-model routing" for workstream 2 needs a per-call model choice; GSD's tiers are the opus/sonnet/haiku vocabulary, with `haiku` as the light tier.
- **Limitations**: documented gaps that affect packaging Ultrathink as a plugin.

## Packaging observations (INFERENCE, not tested)

- Shared denominator: 15 of the 18 GSD runtimes load an Agent-Skills style `SKILL.md` directory (Claude, Kimi, Kimi Code, Codex, Copilot, Antigravity, Cursor, Augment, Trae, Qwen, Hermes, CodeBuddy, Cline, ZCode, pi; plus OpenCode/Kilo, which add commands). One skill bundle plus per-host path mapping covers most of them. Windsurf is the exception: workflows only, workspace scope.
- Hook-capable hosts (candidate gate carriers): Claude, Codex, Kimi, Kimi Code, Qwen, CodeBuddy, Cursor, Copilot, Augment, Antigravity, Cline (tool-level), OpenCode (via plugin), pi (via extension), Hermes (already used). Each needs a live test before the CompletionGate can be called supported. Hosts without any proven hook path should fall back to the skill-return delivery that Prime Agent already uses.
- Cheapest-model routing: only claude, codex, qwen, opencode, copilot, hermes, kilo and pi have concrete GSD tier maps. For the rest, GSD itself cannot pick a cheaper model; a per-host config or `--model` argv would be needed, and `modelMode` passive hosts allow only config or argv selection (MATRIX).
- Installer: GSD's own mechanism (a Node installer writing `~/.<runtime>` dirs with a manifest, hash-checked updates and marker-delimited config blocks) is the model to copy for uninstall safety; `adapters/install.ts` already has the apply/revert shape.
